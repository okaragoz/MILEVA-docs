On this page

Parameter reference ​

A MILEVA run is configured by three mutable structs that main_SphCon receives together:

StructFileHolds
SimConfigconfig/SimConfig.jlGeometry, resolution, solvers, physics switches, time stepping, output. This page documents every field.
MaterialPropertiesconfig/MaterialProperties.jlLayer radii, creep-law constants, yield parameters, phase-transition slopes and density jumps, composition viscosity factors. Summarised at the end of this page.
TemperatureConditionsconfig/TemperatureConditions.jlBoundary temperatures, initial profile, CMB patches. Summarised at the end of this page.

All three are @kwdef structs, so a configuration is plain Julia: build the defaults, overwrite fields, then call validate! on each before the run.

julia
using Plots   # visualization/plot_panels.jl needs Plots loaded first
include("include/mileva.jl"); include("main_SphCon.jl")

cfg  = SimConfig(Nr = 64, Nt = 512)        # keywords at construction
cfg.geometry   = "spherical_annulus"       # or assignment afterwards
cfg.solverType = "mumps"
mat  = MaterialProperties()
temp = TemperatureConditions()
validate!(cfg); validate!(mat); validate!(temp)

history = main_SphCon(cfg, mat, temp)

A parameter file for run_mileva.jl or bin/run_mpi.jl is a Julia script that assigns to cfg, mat and temp in this way.

How to read the tables ​

The Default column is the value in the @kwdef declaration. Read by names the files that read the field (found by searching the source, excluding tests/ and benchmarks/). The status column flags anything that does not do what its name suggests:

  • live: read by the time loop or a solver it calls.

  • unused: no code outside config/SimConfig.jl reads it.

  • refused: validate!(cfg) raises an error if it is set, because the feature behind it is not implemented on the time loop.

  • inert: read only by code that no entry point includes (the AMR prototype under solvers/amr/), or only by a function nothing calls.

  • helper only: read by a helper function that the standard time loop does not call; a custom driver can call it.

  • experimental: live but not recommended; the trade-off is described.

Set what a run depends on

The struct defaults describe an Earth-sized, ALA, composite-capable shell (R_in = 3481 km, R_out = 6371 km, compressibilityMode = "ALA", solverType = "direct", Nr × Nt = 192 × 512). A benchmark sets every switch it depends on explicitly, as benchmarks/hernlund_tackley_annulus.jl does (it clears all optional flags in a loop, then sets the ones it needs).

The geometry exponent m (m=1 cylindrical, m=2 spherical) is the only thing that differs between the two 2-D geometries; the mesh is identical. It enters the radial divergence, the cell measure, the boundary areas and the conductive Nusselt baseline:

∇r⋅f=1rm∂(rmf)∂r,|cell|=Δθ∫ri−1/2ri+1/2rmdr.

For a Venus-sized shell the inner-to-outer boundary area ratio is 0.514 cylindrical against 0.264 spherical (geometry_area_ratio), which is why the cylindrical setting is not used for science runs.

Checking a configuration ​

validate!(cfg) (config/SimConfig.jl) asserts R_out > R_in, Nr ≥ 4, Nt ≥ 8, a known geometry, cmbHeatfluxMode, compressibilityMode and solverType, 0 < dtMin < dtMax and 0 < cflSafety ≤ 1, and refuses the three flags that cannot do what they promise (useAMR, useDruckerPrager, useMPI in 2-D). disp_summary(cfg) prints a one-screen summary. tests/test_config_matrix.jl exercises every geometry, mode and advertised flag; tests/test_config_timeloop.jl runs each advertised configuration through the real time loop.
